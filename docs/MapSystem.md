# 맵 시스템

> 상태: 설계 중, 데이터 모델 부분 구현  
> 관련 코드: `Map.cs`, `MapData.cs`

## 목적

맵을 고정 크기의 청크로 나누고, 전체 맵 데이터와 현재 시뮬레이션에서 활성화된 청크를 분리하여 관리한다. 플레이어는 필요한 청크를 언락해 정착지를 확장한다.

## 핵심 구조

```text
Simulation
└── Map
    └── LinkedList<Chunk> unlockedChunks  (계획)

MapData
└── 전체 맵의 직렬화 데이터
```

### `MapData`

`MapData`는 전체 맵을 생성하거나 저장·불러오기처럼 전체 데이터에 접근할 때 사용하는 직렬화 모델이다.

- 맵 생성 시드
- 청크 단위의 맵 너비와 높이
- 전체 `ChunkData` 배열
- 각 청크의 `GeoSchema`와 언락 상태
- 각 청크에 포함된 전체 `TileData` 배열

### `Map`

`Map`은 실행 중인 시뮬레이션에서 맵을 다루는 런타임 객체다. `Simulation`이 `Map`을 소유하며, `Map`은 언락된 청크만 `LinkedList<Chunk>`에 모아 관리할 계획이다.

`Map`이 담당할 기능은 다음과 같다.

- 언락된 청크 조회 및 순회
- 청크 언락과 다시 잠그기
- 월드 좌표, 청크 좌표, 타일 좌표 간 변환
- 이동 및 건설 가능 여부 조회
- 런타임 청크 상태와 `MapData` 동기화

## 청크 시스템

### 기본 규칙

- 한 청크는 `128 × 128` 타일로 구성한다.
- 맵 크기의 `small`, `medium`, `large`는 청크 개수의 차이를 뜻한다.
- 청크 크기 자체는 맵 크기와 관계없이 고정한다.
- 새 맵에서는 원점을 둘러싼 네 사분면의 청크를 처음부터 언락한다.
- 월드 맵에서는 각 청크의 `GeoSchema`를 알 수 있다.
- 세부 `GeoMorphoma` 구성은 데이터에 존재하더라도 해당 청크를 언락하기 전까지 플레이어에게 공개하지 않는다.

### 언락된 청크만 별도로 관리하는 이유

- 현재 시뮬레이션에서 순회할 데이터의 범위를 줄인다.
- 렌더링 대상을 제한한다.
- 건설 및 이동 연산의 탐색 범위를 제한한다.
- 전체 `MapData`와 현재 활성화된 런타임 상태를 분리한다.

건물과 주민 등 유지해야 할 런타임 객체가 없는 청크는 다시 잠글 수 있도록 할 계획이다. 정확한 잠금 가능 조건과 객체 수 추적 방식은 아직 결정하지 않았다.

### `GeoSchema`

`GeoSchema`는 청크 규모의 거시적인 지형 분류다.

- `plain`: 평원
- `hillRange`: 구릉
- `river`: 강변 또는 강 유역
- `mountainRange`: 산맥
- `sea`: 바다
- `shore`: 해안가

## 타일 시스템

`TileData`는 청크 안의 개별 타일 상태를 표현한다.

- `geoMorphomaType`: 타일의 지형 분류
- `canMove`: 이동 가능 여부
- `canBuild`: 건설 가능 여부

### `GeoMorphomaType`

- `plain`: 평지
- `hill`: 언덕
- `mountain`: 산
- `water`: 물

건물인 `Oikodomema`는 타일 점유 영역에 맞춰 배치한다. `Soma`는 연속적인 월드 좌표로 이동하되, 이동 가능 여부와 길찾기에는 타일 정보를 사용한다. 시각적인 지형물은 반드시 타일 모양에 맞출 필요가 없지만 그 효과는 타일 데이터에 반영한다.

### 점유와 통행

- 다른 지형물이나 건물이 점유한 타일에는 새 건물을 지을 수 없다.
- 평지나 언덕에 건물이 세워지면 해당 점유 타일은 기본적으로 이동할 수 없다.
- 물 타일은 기본적으로 이동할 수 없다.
- 다리가 물 타일의 상태를 바꿀지, 별도의 점유·통행 계층으로 처리할지는 아직 결정하지 않았다.

### 건설 가능 여부 확인 순서

1. 마우스 포인터가 가리키는 월드 위치를 얻는다.
2. 월드 위치를 청크 및 타일 좌표로 변환한다.
3. 대상 청크가 언락되어 런타임에 적재되어 있는지 확인한다.
4. 건물이 점유할 모든 타일의 `canBuild`와 점유 상태를 확인한다.
5. 모든 조건을 만족하면 건설을 예약한다.

건설 예약 자체는 맵이 아니라 `Simulation`의 건설 시스템이 관리한다.

## 저장과 불러오기

저장·불러오기는 다음 흐름으로 구현할 계획이다.

1. 전체 맵을 `MapData`로 보유한다.
2. 게임을 시작하거나 불러올 때 `isUnlocked`인 청크만 런타임 `Chunk`로 만들어 `Map`의 연결 리스트에 넣는다.
3. 게임 중에는 언락된 런타임 청크를 중심으로 시뮬레이션한다.
4. 저장 전에 변경된 런타임 청크를 전체 `MapData`에 반영한다.
5. 전체 `MapData`를 저장한다.

현재 `MapData` 직렬화 클래스와 기본 필드는 구현되어 있다. 실제 파일 저장 형식과 동기화 코드는 아직 구현하지 않았다.

## 월드 맵

- 접근할 수 있는 세계는 우선 직사각형으로 구성한다.
- 바다가 전체 면적의 약 70%를 차지한다는 설정을 사용한다.
- 구형 행성 표현은 현재 범위에서 제외한다.
- 크게 줌 아웃해 월드 맵으로 전환할지, 월드 맵과 정착지 맵을 별도 화면으로 둘지는 미결정이다.

## 현재 구현

- 청크 크기 `128` 정의
- `MapData`, `ChunkData`, `TileData` 직렬화 모델 정의
- `GeoSchema` 및 `GeoMorphomaType` 정의
- `Map` 런타임 클래스 골격 작성

## 미결정 사항

- 런타임 `Chunk` 클래스의 구체적인 데이터 구조
- 청크를 다시 잠글 수 있는 정확한 조건
- 청크 객체 수를 추적하는 방법
- 길찾기 알고리즘과 탐색 범위
- 다리의 점유 및 통행 처리 방식
- 월드 맵과 정착지 맵의 화면 전환 방식
