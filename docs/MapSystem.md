# 맵 시스템

> 상태: 설계 중, 데이터 모델 부분 구현  
> 관련 코드: `Map.cs`, `MapData.cs`, `MapRenderer.cs`, `Chunk.cs`

## 목적

맵은 고정 크기의 청크로 구성되며 전체 맵 데이터와 현재 시뮬레이션에서 활성화된 청크를 분리하여 관리. 플레이어는 필요한 청크를 언락해 정착지를 확장함.

## 핵심 구조

```text
Simulation
└── Map
    └── LinkedList<Chunk> unlockedChunks  (계획)

MapData
└── 전체 맵의 직렬화 데이터
```

### `MapData`

전체 맵을 생성하거나 저장·불러오기처럼 전체 데이터에 접근할 때 사용하는 직렬화 구조.

- 맵 생성 시드
- 청크 단위의 맵 너비와 높이
- 전체 `ChunkData` 배열
- 각 청크의 `GeoSchema`와 언락 상태
- 각 청크에 포함된 전체 `TileData` 배열

### `Map`

`Map`은 실행 중인 시뮬레이션에서 맵을 다루는 런타임 객체임. `Simulation` has a `Map`, `Map`은 `MapData`를 가지지만 특히 Unlocked된 Chunk들은 `LinkedList<Chunk>`에 모아 관리함.

`Map`의 역할은 다음과 같음:

- 언락된 청크 조회 및 순회
- 청크 언락과 다시 잠그기
- 월드 좌표, 청크 좌표, 타일 좌표 간 변환
- 이동 및 건설 가능 여부 조회
- 런타임 청크 상태와 `MapData` 동기화

### `MapRenderer`

`MapRenderer`는 Map Instance를 실제 게임에 투영시켜주는 Component.

## 청크 시스템

### 기본 규칙

- 한 청크는 `128 × 128` 타일로 구성됨. 청크 크기 자체는 맵 크기와 상관 없이 일정.
- 맵 크기의 `small`, `medium`, `large`는 오직 청크 개수의 차이를 뜻한다.
- 새 맵에서는 원점을 둘러싼 네 사분면의 청크는 처음부터 언락됨.
- 월드 맵에서는 각 청크의 `GeoSchema`를 알 수 있음
- 세부 `GeoMorphoma` 구성은 데이터에 존재하더라도 해당 청크를 언락하기 전까지 플레이어에게 공개하지 않음. (유저모드가 만약 나온다면 이거 뜯어서 보여주는 모드도 나오겠네)

### 언락된 청크만 별도로 관리하는 이유
- 렌더링 대상을 제한하려고.
- 건설 및 이동 연산의 탐색 범위를 제한할 수 있을거같아서.
- 전체 `MapData`와 현재 활성화된 런타임 상태를 분리하면 좋을거같아서.


건물과 주민 등 유지해야 할 런타임 객체가 없는 청크는 다시 잠글 수 있도록 할 계획인데, 잠금 조건은 아무런 `soma`가 없고 아무런 `oikodomema`가 없을 때 가능하도록
개체 수 추적 방식은 건설에서 동작할 예정인데, 건설을 할 시 해당 청크의 건물 Linked List에 넣을 생각이었는데 이러면 `MapData`에 해당 정보를 넣을 수가 없네. 새로 Json에 그런 규격을 넣기도 이상하고 어떻게 하지? 

### `GeoSchema`
`GeoSchema`는 청크 규모의 거시적인 지형 분류임.
- `plain`: 평원
- `hillRange`: 구릉
- `river`: 강변 또는 강 유역
- `mountainRange`: 산맥
- `sea`: 바다
- `shore`: 해안가

## 타일 시스템
`TileData`는 청크 안의 개별 타일의 상태를 나타냄.
- `geoMorphomaType`: 타일의 지형 분류
- `canMove`: 이동 가능 여부
- `canBuild`: 건설 가능 여부

### `GeoMorphomaType`
`GeoMorphoma`는 타일 규모의 미시적 지형
- `plain`: 평지
- `hill`: 언덕
- `mountain`: 산
- `water`: 물

건물인 `Oikodomema`는 타일 점유 영역에 맞춰 배치한다. `Soma`는 연속적인 월드 좌표로 이동하되, 이동 가능 여부와 길찾기에는 타일 정보를 사용한다. 시각적인 지형물은 반드시 타일 모양에 맞출 필요가 없지만 그 효과는 타일 데이터에 반영한다.

### 점유와 통행

- 다른 지형물이나 건물이 점유한 타일에는 새 건물을 지을 수 없다.
- 평지나 언덕에 건물이 세워지면 해당 점유 타일은 기본적으로 이동할 수 없다.
- 물 타일은 기본적으로 이동할 수 없다.
- 다리가 물 타일의 상태를 바꿀지, 별도의 점유·통행 계층으로 처리할지는 아직 결정하지 않았다.

### 건설 가능 여부 확인 순서

1. 마우스 포인터가 가리키는 월드 위치를 얻는다.
2. 월드 위치를 청크 및 타일 좌표로 변환한다.
3. 대상 청크가 언락되어 런타임에 적재되어 있는지 확인한다.
4. 건물이 점유할 모든 타일의 `canBuild`와 점유 상태를 확인한다.
5. 모든 조건을 만족하면 건설을 예약한다.

건설 예약 자체는 맵이 아니라 `Simulation`의 건설 시스템이 관리한다.

## Save and Load

저장·불러오기는 다음과 같은 흐름으로 동작함.

1. Simulation이 전체 맵을 `Map`의 `MapData`로 보유.
2. 게임을 시작하거나 불러올 때 `isUnlocked`인 청크만 런타임 `Chunk`로 만들어 `Map`의 LinkedList에 적재.
3. 모든 맵 연산은 UnlockedChunk에서만 유효하며 해당 청크에서 연산이 발생하면 Reference Type이기에 알아서 MapData에 반영.

## 월드 맵
- 행성 모양을 구형으로 하는 것은 현재로써는 잠시 보류.
- 그렇기에 접근할 수 있는 세계는 우선 직사각형으로 구성.
- 프로스트펑크처럼 크게 줌 아웃해 월드 맵으로 전환할지, 스텔라리스나 림월드처럼 월드 맵과 정착지 맵을 별도 화면으로 둘지는 아직 미결정 사안.

## 현재 구현

- 청크 크기 `128` 정의
- `MapData`, `ChunkData`, `TileData` 직렬화 모델 정의
- `GeoSchema` 및 `GeoMorphomaType` 정의
- `Map` 런타임 클래스 골격 작성

## 미결정 사항

- 런타임 `Chunk` 클래스의 구체적인 데이터 구조
- 청크를 다시 잠글 수 있는 정확한 조건
- 청크 객체 수를 추적하는 방법
- 길찾기 알고리즘과 탐색 범위
- 다리의 점유 및 통행 처리 방식
- 월드 맵과 정착지 맵의 화면 전환 방식
